# 適用手順 — 送信失敗(写真あり)の対策 / 2026-08-01

「写真を付けて記入すると送信失敗になる」への対策一式です。
**フロント(GitHub Pages)** と **GAS** の両方に変更があります。順番はどちらからでも構いませんが、
GAS を先に入れると、フロントが古いままでも壊れません(逆も安全に作ってあります)。

---

## 1. GAS 側(コピペ + 再デプロイ)

GAS エディタで、下の **7ファイル**の中身を貼り替えます(ファイル名は既存のまま)。

| ファイル | 変更点 |
|---|---|
| `10_Lib_Sheet.gs` | `_normKey` / `_findHeaderIndex` / **`batchIdExists`**(重複チェック)を追加 |
| `20_Api_Members.gs` | `apiUploadPhoto` が保存先フォルダ(`folder`)を受け取れるように |
| `21_Api_Visits.gs` | アップ済み写真の `photo_url` / `field2_photo_url` を受け取れるように |
| `22_Api_Facility.gs` | 同上(`photo_url`) |
| `23_Api_Notes.gs` | 同上(`photo_url`。写真だけの覚書も許可) |
| `27_Api_Todos.gs` | 追記を `appendRowByHeaders` に(列順に依存しない + `batch_id` 対応) |
| `28_Api_Posts.gs` | **冪等化**(同じ batch_id は二度書かない)+ **ScriptLock** で直列化 |

貼り替えたら **「デプロイ」→「デプロイを管理」→ 既存のウェブアプリを編集 → 新バージョンで再デプロイ**。
(URL は変わりません)

### 併せてやると良いこと(任意・1分)

`todos` シートのヘッダ行の右端に **`batch_id`** という列を1つ足してください(半角・前後空白なし)。
これで Todo も再送で二重登録されなくなります。無くても動きます。

`visits` / `facility_ops` / `notes` の `batch_id` 列は既にあるはずです。念のため確認してください。
**この列が無いと二重投稿防止が効きません**(エラーにはならず、従来どおりの動作になります)。

## 2. フロント側(GitHub へ push)

変更ファイル:

| ファイル | 変更点 |
|---|---|
| `src/config.js` | 画像圧縮を長辺1280/品質0.72 + **400KB上限**、action別タイムアウト、リトライ設定 |
| `src/utils.js` | 上限バイト数に収まるまで自動で圧縮を強める(+ `dataUrlBytes`) |
| `src/api.js` | action別タイムアウト・自動リトライ(冪等な action のみ)・圏外判定 |
| `src/pages/Compose.js` | 写真を1枚ずつ先送り → 本体は URL だけ / 下書き自動保存 / 進捗表示 / 再送ボタン |
| `src/styles.css` | 案内バナー・進捗表示のスタイル追加 |
| `service-worker.js` | `CACHE_NAME` を **v58** に(更新バナーを出すため) |

push 後、アプリを開くと「更新」バナーが出ます。タップすると新版に切り替わります。
出ない場合はホーム画面アイコンを長押し削除 → 再インストール。

---

## 3. 確認のしかた(実地で1回)

1. 田んぼで、写真2枚 + 水位 + メモを入れて「記す」
2. 送信中に「写真を送っています(1/2)…」と進捗が出る
3. もし失敗しても、**入力は消えない**。ボタンが「もう一度送る」に変わる → 押す
4. スプレッドシートを見て、**行が二重になっていない**ことを確認

うまくいかない時は、画面に出たエラー文言を**最後まで**控えてください。
`[addPost] …`(どの通信で)、`【保存済み: …】`(どこまで保存されたか)が入っています。
